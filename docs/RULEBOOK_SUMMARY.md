# HacXLerate 2026 — Round 1 rulebook summary (source: official PDF, 17 pages)

**Format:** 24h *physical* campus hackathon, Round 1 window Oct 5–11, 2026. Team of 3–5, same college, valid college ID, own laptops + chargers. Venue Wi-Fi is "as per college arrangements" — prep offline.
**Pipeline:** Round 1 -> Top 50 -> Round 2 -> Top 7 -> Grand Finale. Top 3 per college get recognition (does NOT mean Round 2).

## Clock
- Platform access (byteXL Hackathon Platform) emailed ~2–3h before start. Check spam. Log in early. The challenge unlocks only at the official start.
- Arrive >= 30 min before start for the briefing.
- **First 2h: choose + LOCK one problem statement. Only the Team Lead can lock. The lock is permanent through Round 1 -> 2 -> Finale. Missing the lock window can disqualify.**
- Remaining 22h: build, test, deploy, repo, project info, submit.
- Deadline = start time + 24h (e.g. 10:00 -> 10:00 next day). Late = rejected.

## Submission (on the platform; ANY team member can submit)
1. Project info: title, summary, solution description, other requested fields
2. GitHub repo: accessible to evaluators, README, stack + implementation details
3. Working deployment link (Nimbus by byteXL is offered as the dev/deploy env; other tools are allowed)
4. Challenge-specific info
- Resubmission is allowed until the deadline; the latest VALID submission counts. Submit an early baseline.

## Evaluation
1. **Automated gate:** checks the challenge's mandatory functionalities. Below the threshold = no human evaluation.
2. **Human:** Problem Understanding, Functionality, Technical Execution, Innovation & Creativity, UX, Overall Quality, Deployment, Scalability/Potential. Weights vary per challenge.
- A live demo is not mandatory, but evaluators may ask: stay reachable and be able to explain everything.

## Rules that disqualify
Not locking in time · changing the lock · missing mandatory functionality · plagiarism / copied or stolen code · falsified info · unauthorised team changes · **inaccessible/invalid links** · manipulating the platform or auto-evaluation · misconduct.

## AI & stack
AI tools fully allowed (coding, debugging, design, docs). The team must understand and be able to explain the work. Any language/framework unless the challenge says otherwise. Public libraries/APIs OK.

## Support
Zoom helpline (link given at the briefing): guidance only, no debugging for you. Official communications supersede WhatsApp rumours.
